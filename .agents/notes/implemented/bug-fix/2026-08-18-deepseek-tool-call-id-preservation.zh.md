# Agent Note: 保留流式工具调用的非空身份

Status: implemented

English | [English](2026-08-18-deepseek-tool-call-id-preservation.md)

## Problem

兼容 DeepSeek 的流式响应可能在第一个分片中提供工具调用身份，而在后续参数分片中显式发送空的 `tool_calls[].id`。DeepSeek 适配器会把每个已定义的线值写入累计调用，因此空的后续值会覆盖原本可用的身份。最终工具调用块携带空 `CallId`，下游无法关联工具结果，合法的流式续接会因工具血缘未解析而失败。

## Decision

DeepSeek 转换器只有在线值非空时才更新累计的工具调用身份。因此，后续只携带参数的分片不会覆盖第一个非空 ID；如果之后出现另一个非空线值，仍允许它修正或替换累计身份。参数片段、函数名、结束原因、用量和输出的线协议保持不变。适配器的中英文 README 在其它流式规则旁记录这一供应商行为。

## Alternatives considered

**收到空工具调用 ID 后拒绝整个流。** 不采用，因为当更早分片已经建立调用身份时，参数分片中的空 ID 是兼容供应商的有效输入；拒绝它会把可恢复的线差异变成请求失败。

**在工具组装或续接处理的下游修复空身份。** 不采用，因为适配器负责把供应商线数据转换为稳定调用身份，下游不应携带供应商特有的修复逻辑。

**只接受第一个非空 ID，忽略后续所有非空 ID。** 不采用，因为后续非空值可能是供应商修正后的身份；最小不变量是忽略空覆盖，而不是冻结所有后续非空值。

## Consequences

分片的 DeepSeek 工具调用会在空参数分片之后继续保留已建立的身份，因此工具结果关联和 Agent 续接可以正常工作。始终没有提供非空 ID 的流仍然输出原有的空身份，并保留下游对真正不可识别调用的失败行为。请求和响应协议字段不变。

## Testing

适配器转换测试复现真实抓包形态：第一个分片提供非空 ID，后续参数分片提供空 ID，并要求每个输出分片及最终工具调用块都保留稳定身份。`llm-deepseek` 聚焦 Vitest 文件通过 30 个测试，包级 TypeScript 构建通过，中英文 README 配对校验通过。
